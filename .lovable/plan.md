## Add Google Sign-In to auth flow

Add a "Continue with Google" button to the existing email/password auth UI so users can one-tap sign up or log in. Email/password stays as the default; Google becomes a peer option.

### What changes

1. **Enable Google provider** via Lovable Cloud managed OAuth (no credentials needed from you — uses Lovable's managed Google client). Email/password stays enabled.

2. **Generate the Lovable auth module** (`src/integrations/lovable/`) via the social-auth tool. This installs `@lovable.dev/cloud-auth-js` and wires `lovable.auth.signInWithOAuth("google", …)` against the existing Supabase backend.

3. **Update `src/components/auth-form.tsx`**:
   - Add a "Continue with Google" button above the email/password form, with a subtle "or" divider below it.
   - On click: call `lovable.auth.signInWithOAuth("google", { redirect_uri: window.location.origin })`. The browser redirects to Google, then back to `/`, where `HomeRoute` already routes new users into the EntryFlow (name → location → themes → groups → first walk) and returning users into `WalkTab`.
   - On success, also write `wc_last_auth = "google"` so the demo banner / return CTA says "Log in with Google" next time.

4. **Update `src/components/friend-walk/quick-signup-sheet.tsx`** (and any other auth surfaces) — they all render `<AuthForm />`, so the Google button shows up everywhere automatically. No extra work.

5. **Profile linkage**: Google signup fires the existing `handle_new_user` trigger which creates a `profiles` row using `raw_user_meta_data->>'display_name'` (Google supplies `name` / `full_name`; we'll pass `display_name` through the OAuth `data` mapping if available, otherwise the EntryFlow's Name slide collects it). No schema change.

### Files touched

- New: `src/integrations/lovable/*` (auto-generated by the tool — do not hand-edit)
- Edit: `src/components/auth-form.tsx` (add Google button + divider + handler)
- Edit: `package.json` (auto via tool — adds `@lovable.dev/cloud-auth-js`)
- Tool calls: `supabase--configure_social_auth` with `providers: ["google"]` (keep email enabled)

No DB migration. No RLS change. No new routes.

### UX notes

- Google button placed **above** the email form (industry-standard placement; faster path).
- Uses the existing forest/cream design tokens — no new colors. Outlined card style with the multi-color Google "G" mark to match 2026 conventions.
- Same button shows in both Sign In and Create Account tabs (Google handles both with one click).
- The 30-day Plus trial intent (`PLAN_INTENT_KEY` in localStorage) is set **before** triggering Google redirect, so the post-OAuth checkout auto-open in `auth-prompt.tsx` still fires for users who picked Plus.

### Out of scope

- Apple Sign-In (can add later — same pattern, just `providers: ["apple"]`).
- Custom Google OAuth credentials (BYOK) — using Lovable's managed client.
